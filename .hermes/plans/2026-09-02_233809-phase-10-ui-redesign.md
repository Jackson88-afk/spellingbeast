# Phase 10 UI redesign implementation plan

> **For Hermes:** Execute one task at a time with the dev agent. Do not start the next task until the coordinator verifies the previous one.

**Goal:** Give the entire SpellingBeast webapp a simple, modern, centered, child-friendly visual system that keeps each flow understandable within one viewport where practical, without changing product behavior.

**Architecture:** Keep the existing vanilla HTML/CSS/JavaScript architecture, selectors, state machine, localization, persistence, and Web Speech API. Establish one small design system first, then apply it page by page. UI changes must remain presentation-only unless an accessibility fix is required and explicitly verified.

**Tech Stack:** Existing native HTML, CSS, and JavaScript; no React, Tailwind, build system, external audio service, or new product feature.

---

## Locked design direction

- Simple modern interface with restrained rounded surfaces, clear spacing, and a centered main content column.
- One primary action per screen; secondary actions remain visually subordinate.
- Prefer a one-screen composition at common laptop and mobile sizes; avoid unnecessary vertical and horizontal scrolling.
- Large controls suitable for children ages 6–12; touch targets at least 44px.
- Short labels, strong hierarchy, high contrast, obvious selected/success/error states.
- Preserve the existing warm tone only if it passes contrast and remains visually restrained; no rainbow palette, aggressive gradients, glassmorphism, decorative dashboard, or excessive card grids.
- No XP, points, badges, avatars, streaks, complex animation, definitions, accounts, or other excluded v1 features.
- Preserve English default, Chinese toggle, localStorage language persistence, practice behavior, mistake lifecycle, and audio behavior.

**Objective:** Make the first screen immediately understandable and usable by a child in one centered composition.

**Scope:** Improve heading hierarchy, primary Add Word List action, saved-list rows/cards, Practice actions, Mistakes entry point, empty state, and language control placement. Keep all existing actions and text meaning.

### TASK-103 — Redesign the create/import word-list screen

**Objective:** Make word-list creation/import a short, focused, single-page task.

**Scope:** Center the form, make the list-name and textarea relationship clear, group TXT/CSV upload controls without clutter, keep validation feedback close to the relevant control, and make Save/Cancel hierarchy obvious.

### TASK-104 — Redesign practice setup / session-size selection

**Objective:** Make choosing a list and session size fast and visually obvious.

**Scope:** Strengthen selected state for 5/10/20/All, use accessible pressed/selection semantics where compatible with existing behavior, simplify spacing, and make Start action the clear primary action.

**Acceptance:** Selected size is obvious visually and to assistive technology; existing fallback behavior for lists smaller than the requested size is unchanged; no new options are added.

### TASK-105 — Redesign the active practice screen

**Objective:** Keep the child focused on one spelling action at a time.

**Scope:** Center the current challenge, give Play Word, answer input, Submit, feedback, and Next a clear order; keep progress visible but quiet; preserve audio failure messaging and feedback timing.

**Acceptance:** The target word remains hidden until submission; the existing Play → Type → Submit → Feedback → Next loop is unchanged; input focus and keyboard submission continue to work; no unnecessary page scrolling.

### TASK-106 — Redesign session summary and missed-word presentation

**Objective:** Make completion and next steps understandable at a glance.

**Scope:** Create a clear score hierarchy, concise attempted/correct/missed summary, readable missed-word rows/cards, and a prominent Practice Mistakes action only when applicable. Keep correct spelling reveal timing and all existing navigation.

**Acceptance:** All required summary information remains present; children can identify their result and next action quickly; no gamification is introduced.

### TASK-107 — Redesign the Mistakes screen and all-caught-up state

**Objective:** Make active mistakes easy to understand and practice.

**Scope:** Improve count, word list readability, Practice Mistakes action, empty state, and All Caught Up state using the shared design system.

**Acceptance:** Active mistake count and words remain accurate; Practice Mistakes and return actions work; empty and completed states are clear without extra explanatory text.

### TASK-108 — Accessibility, responsive, and focus hardening

**Objective:** Resolve cross-page usability issues discovered during the redesign.

**Scope:** Confirm 44px minimum targets, visible focus, logical tab order, accessible selected states, stable focus after view changes, no horizontal overflow, readable text, and reduced-motion-safe behavior if any motion was retained.

**Acceptance:** Keyboard-only traversal works across every flow; mobile layouts work at approximately 390px width; desktop layouts remain centered without excessive empty space; contrast checks pass for important text and controls.

## Execution order and ownership

1. Coordinator and user approve the design contract from TASK-100.
2. Dev agent executes exactly one task per handoff, using the installed UI skills.
3. Dev agent runs direct tests and reports changed files.
4. Coordinator independently checks the diff, browser behavior, visual result, responsive layout, accessibility, and spec compliance.
5. Only after acceptance does the next task begin.
6. No automatic commit or push unless explicitly requested.

## Main risks

- Replacing HTML structure can break fixed selectors, event binding, localization, or state restoration.
- Over-centering can make list-heavy screens inefficient; centered composition should not mean every element is centered.
- Rounded surfaces and shadows can reduce contrast or consume too much viewport height.
- A visually stronger summary must not introduce game-like scoring, history, or rewards outside v1.
- Global CSS changes can affect every flow, so TASK-101 must be small and verified before page-specific work.
